# 4. EVALUATION METRICS

I want detailed, quantitative metrics for **each model, each language, and each document category**.

Implement metrics only when valid ground truth exists.

## A. Text extraction accuracy

Calculate:

- Character Error Rate (CER)
- Word Error Rate (WER)
- Character Accuracy, explicitly defined
- Word Accuracy, explicitly defined
- Normalized Edit Distance
- Exact Match Rate
- Precision/Recall/F1 for clearly defined text-matching units, where appropriate

Evaluate English and Arabic separately.

For Arabic, support configurable normalization:

- Diacritics
- Alef variants
- Hamza handling
- Tatweel
- Unicode normalization
- Whitespace

Preserve both raw-text and normalized-text scores.

Do not silently remove meaningful characters or change the reference text.

## B. Document layout analysis

Evaluate:

- Layout detection precision
- Layout detection recall
- Layout detection F1
- Bounding-box IoU
- mAP when valid detection annotations exist
- Per-class performance

Possible layout categories:

- Title
- Heading
- Paragraph
- Table
- Figure
- Chart
- Caption
- Header
- Footer
- List
- Other annotated classes

Map model-specific labels into a canonical taxonomy.

Use consistent IoU thresholds and matching rules.

Do not penalize a model for categories that the benchmark itself does not annotate.

## C. Reading order accuracy

Evaluate:

- Reading-order accuracy
- Normalized inversion rate
- Kendall's Tau where applicable
- Multi-column reading-order correctness
- Arabic right-to-left reading-order correctness

Only evaluate when reliable reading-order references exist.

## D. Table extraction

Evaluate:

- Table detection precision/recall/F1
- Table bounding-box IoU
- Table structure similarity using TEDS where applicable
- Cell text accuracy
- Cell matching F1
- Row and column structure correctness
- Merged-cell recognition
- Header preservation

Include simple and complex tables when the datasets support them.

Handle models that return plain text separately from models that return structured HTML/Markdown/cell annotations.

Do not substitute superficial string similarity for structural evaluation.

## E. Charts and figures

Evaluate chart capabilities separately:

- Chart/figure detection accuracy
- Chart region localization
- Chart type classification accuracy
- Text extraction from charts
- Data extraction accuracy when numeric chart ground truth exists
- Structural completeness where annotated

Possible chart types:

- Bar
- Line
- Pie
- Scatter
- Area
- Mixed charts

Distinguish **detecting a chart**, **reading text inside a chart**, and **recovering chart data**.

These are different capabilities and must have different scores.

Do not invent chart-level scores when reference annotations are absent.

## F. Arabic-specific evaluation

Report:

- Arabic CER and WER
- Arabic normalized CER and WER
- Mixed Arabic/English performance
- Numeral recognition when annotated
- Arabic reading order
- Arabic table extraction performance
- RTL layout handling

Report unsupported/untested categories explicitly.

## G. Performance and efficiency

Record:

- Model initialization time
- Inference time
- Total processing time
- Seconds per page
- Throughput (pages/minute)
- Peak RAM usage
- Peak GPU VRAM usage, if available
- CPU/GPU device
- Model weight size
- Model/dependency versions
- Failed pages/documents
- Success rate
- External API latency and cost, where applicable

Distinguish cold-start and warm inference.

Exclude one-time installations and downloads from inference latency.

Track preprocessing, inference, and postprocessing separately where practical.

# 5. EVALUATION FAIRNESS AND STATISTICAL RIGOR

To make the benchmark scientifically credible:

1. Use identical frozen evaluation documents.
2. Use identical evaluation normalization and matching logic.
3. Record preprocessing differences.
4. Record resolution and DPI settings.
5. Track hardware and environment.
6. Record model versions and configuration.
7. Distinguish OCR-only from end-to-end document understanding.
8. Avoid giving one model an unfair advantage through manual corrections.
9. Never change the test dataset after seeing model results without versioning it.
10. Preserve raw outputs so evaluation metrics can be recalculated.

Where feasible, add:

- Per-document metric distributions
- Median, mean, standard deviation
- 95% confidence intervals using document-level bootstrap resampling
- Failure counts and failure categories
- Performance by document type
- Performance by page complexity

Distinguish metrics where **higher is better** from those where **lower is better**.

Do not report a single overall score without explaining how it was calculated.

### Scoring system

Produce independent scores for:

- English OCR
- Arabic OCR
- Layout analysis
- Table understanding
- Chart understanding
- Reading order
- Speed
- Resource efficiency
- Reliability

Use a consistent 0–100 display scale only where a mathematically justified transformation exists.

Optionally define a weighted composite score, but make weights configurable, explain them, and avoid treating missing metrics as zero.

A model must not rank highly simply because unsupported categories were excluded without disclosure.
