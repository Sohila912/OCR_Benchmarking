OCR benchmark: management progress report

As of 9 November 2026 · Arabic and English OCR · Interim results

Current position

The shared benchmarking framework is complete, all nine planned model candidates have been assessed or attempted, and several models have produced saved outputs. No model has completed the full 1,135-page evaluation. There is no validated overall winner or finished cross-model comparison yet.

The clearest measured evaluation checkpoint is PaddleOCR: 200 evaluation pages converted without failures, with text scores available for 199 pages. Tesseract has the largest saved evaluation coverage: 437 pages, with no OCR failures at its last checkpoint. Baidu has now reached 14 successful hosted development pages.

Measured text recognition results

CER and WER are character and word error rates; lower is better. A successful conversion means the pipeline produced a completed output, not that the text was correct. These rows are separate checkpoints, not a performance ranking.

Model and cohort Text-scored pages, English / Arabic English CER / WER Arabic CER / WER
PaddleOCR — 200-page evaluation subset 99 / 100 14.17% / 23.48% 51.53% / 71.34%
PaddleOCR — 20-page development set 10 / 10 7.98% / 23.75% 56.29% / 77.29%
Tesseract — 20-page development set 10 / 10 8.96% / 24.21% 29.04% / 45.77%
Docling + Tesseract — development run 10 / 9 26.69% / 40.09% 50.26% / 67.47%

All rates above use the shared text normalization policy. English is scored against independently allocated reference-region text; Arabic uses page-content text, so their reference scopes differ. Paddle's evaluation subset selected the first 100 pages per language deterministically; it is not a random corpus sample. One English evaluation page lacked a text reference and was not scored. The Docling + Tesseract timeout is also excluded from text scoring, not zero-filled. Source-document independence is unverified. These limits prevent an overall accuracy ranking from these checkpoints.

Baidu's 14 conversions and EasyOCR's eight English successes do not yet have published text accuracy scores in their current reports. No full-evaluation score is available for Tesseract's incomplete 437-page run.

Runtime, resources and evidence

Paddle's 200-page batch took 97.89 minutes, with sampled peak process and descendant RSS of 0.71 GiB. Timings include fresh worker startup and related processing overhead; sampled RSS can miss short peaks. These are measured local CPU results, not projected full-run performance.

The laptop has 12 GB installed RAM (about 11.74 GiB usable) and an MX350 with 2-GiB VRAM. Available RAM varies with other applications. D: holds downloaded assets, isolated runtimes, native outputs and reviewed copies; disk capacity does not replace physical RAM. Windows paging settings have not been changed.

Baidu runs on a free external hosted demo, so its quota, hardware and timing boundary differ from local CPU tests. No paid service was enabled. Model support for layout, reading order and tables varies; unsupported outputs and missing references are recorded explicitly rather than treated as zero scores.

What remains to finish

  1. Complete consistent evaluation coverage. Paddle has 935 pages remaining. Tesseract has 698 remaining; its saved run must be recovered with its recorded execution identity before continuation, or replaced by a clearly versioned run.
  2. Finish the development checkpoints. Baidu has six pages left when free quota permits. Docling + Tesseract has one timeout to resolve. EasyOCR and Granite need their recorded native, memory or generation failures investigated.
  3. Score and review saved outputs. In particular, distinguish Baidu/EasyOCR conversion completion from text quality, and report failures and coverage.
  4. Produce the final comparison. Use matching cohorts, disclose local versus hosted execution, and keep text, structure and resource results separate.

Management takeaway: the project has a working, checkpointed benchmark and useful interim evidence. The remaining work is completing comparable evaluations and resolving execution blockers.
